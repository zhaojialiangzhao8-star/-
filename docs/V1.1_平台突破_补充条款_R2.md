## 补充 0：数据前提（修正）

### R1 的错误

要求「起始日早于 2021-06 的标的 ≥ 4,500 只」—— **这不现实**。2021 年 6 月以后上市的股票，本来就不可能拥有更早的 K 线。

### 修正后的验收方法

不再用「多少只股票从 2021 年开始」，改为**逐股核对完整性**：

```
对每只股票 i：
  上市日 listing_i   = 可查则用真实上市日，不可查则用首根 K 线日期（标注为近似）
  应有交易日 expected_i = 日历中 [max(2021-01-04, listing_i), 数据截止日] 的交易日数
  实际交易日 actual_i   = 该股票实际有 K 线的交易日数
  完整度 comp_i = actual_i / expected_i
```

### 验收标准（三条，都要满足）

| 指标 | 目标 | 说明 |
|---|---|---|
| **完整度中位数** | ≥ 0.95 | 一半以上的票数据是完整的 |
| **完整度 < 0.80 的股票数** | ≤ 100 只 | 允许少量长期停牌股 |
| **全市场日均横截面宽度** | ≥ 4,000 只（数据截止前 250 日） | 近期不能缺票 |

### 分类处理数据缺口

```
A 类 数据覆盖不足（该有 K 线但没有）    → 需要补数据
B 类 当时尚未上市                      → 正常，不参与该时段回测
C 类 退市 / 长期停牌                    → 保留历史 K 线到停牌日，之后不参与
```

**回测时必须按「该股票在该日期是否可获得」动态过滤**，而不是要求全池子都从 2021 年开始。

## 补充 5：信号量与仓位约束（修正 R1 的硬错误）

### R1 的三个错误

**错误 A：5 只 × 25% = 125%，超 100%**

```python
MAX_POSITIONS = 5
MAX_POSITION_PCT = 0.25
5 × 0.25 = 1.25 > 1.00   ← 不可能实现
```

**错误 B：说「不控信号量 = 随机抽样」不准确**

真正的问题是：**当信号数超过资金承载能力时，系统如何确定买谁**。这需要固定的排序规则，不是"随机"。

**错误 C：缺组合总仓位上限和可用资金约束**

### 修正后的约束体系（四层）

```python
init_cash        = 100_000
risk_per_trade   = 0.005      # 单笔最大亏损 = 净值 × 0.5% = 500 元
max_positions    = 5          # 最多 5 只
max_position_pct = 0.20       # 单票最大 20%（5 × 20% = 100% 刚好）
max_gross_exposure = 0.95     # 总仓位上限 95%，留 5% 现金
max_per_day      = 3          # 每天最多新开 3 只（避免一天打满）
```

**约束的优先级**（四层都要过）：

```
1. 单笔风险   股数 ≤ risk_amount / (买入价 - 止损价)
2. 单票上限   股数 × 买入价 ≤ 净值 × 0.20
3. 总仓位     现有持仓市值 + 本笔金额 ≤ 净值 × 0.95
4. 可用资金   本笔金额 + 手续费 ≤ 现金
────────────────────────────────────────
最终股数 = min(以上四个) 向下取整到 100 股
```

### 排序规则（R1 说"必须固定"，本版给出三组）

```
S1  突破幅度降序        (close[T] - 上沿) / 上沿
S2  平台长度降序        平台窗口内横盘天数
S3  平台振幅升序        (上沿 - 下沿) / 下沿（越窄越优先）
```

**三组都要跑，报告里对比。排序规则本身是实验变量，不能事后挑。**

### 未入选的信号必须记录

回测输出里要有：

```
每日信号总数
每日实际下单数（受 max_per_day 限制）
每日因 max_positions 拒单数
每日因资金不足拒单数
被拒比例（拒单 / 信号总数）
```

**判断标准**：

```
被拒比例 < 30%   → 回测可信
被拒比例 30-70%  → 可信度中等，报告标注
被拒比例 > 70%   → 结果高度依赖排序规则，不能单独作为策略评价
```

## 补充 6：平台定义（修正 R1 的定义问题）

### 6.1 P1 改名

```
R1 名：振幅法 / 平台突破
新名：区间收敛突破（Range Contraction Breakout）

理由：这个定义本质是「过去 N 日振幅小 → 突破上沿」，
      是"区间收敛"不是"平台"。用词要和数学定义一致。
```

公式不变：

```
窗口 [T-N, T-1]（不含 T 日）
上沿 = max(high[T-N .. T-1])
下沿 = min(low[T-N .. T-1])
振幅 = (上沿 - 下沿) / 下沿
成立：振幅 < R
突破：close[T] > 上沿
```

### 6.2 P3 修正未来函数隐患

**R1 的错误**：

```python
突破条件：close[T] > MA20[T] + 1σ20[T]
```

`MA20[T]` 和 `σ20[T]` 都包含 `close[T]`。虽然信号在收盘后生成不算严格未来函数，但**当天大涨会把阈值抬高，导致"越涨越难突破"** —— 逻辑上不自洽。

**修正**：用 **T-1 日已确定的布林带**作为突破阈值。

```python
MA20_prev = mean(close[T-20 .. T-1])
σ20_prev  = std(close[T-20 .. T-1])
带宽_prev = 4 × σ20_prev / MA20_prev

成立：带宽_prev 在过去 250 日处于最低 20% 分位
突破：close[T] > MA20_prev + 1σ20_prev
```

**这样阈值完全由历史数据决定，当天的价格只是"被比较的对象"。**

### 6.3 P4 需要独立验证

**R1 的问题**：低斜率 + 低 R² 不一定代表有效平台，也可能只是杂乱震荡。

**修正**：P4 增加两个附加条件，并且**单独做一次验证**：

```
成立条件（三个都要满足）：
  1. |slope| / mean(close) < 0.001        （趋势平）
  2. R² < 0.5                             （不像是趋势，但也许是杂乱）
  3. 窗口内收盘价穿越 MA 的次数 ≥ 5        （确实在震荡，不是一条横线）
  4. 窗口内收盘价的标准差 / 均值 < 0.08    （振幅确实小）
```

**附加验证**：单独统计「满足 P4 且后续 20 日振幅 < 10%」的比例。如果这个比例 < 60%，说明 P4 识别出来的不是平台。

## 补充 7：收益口径（修正 R1 的隔夜表述错误）

### R1 的错误

写「实际资金占用 = T+1 开盘 到 T+6 开盘（含一个隔夜）」。

**这是错的。** T+1 开盘买入、T+6 开盘卖出，中间跨越：

```
T+1 白天的持仓 + T+1 夜 → T+2 日的隔夜
T+2 白天 + T+2 夜 → T+3 隔夜
...
T+5 白天 + T+5 夜 → T+6 日的隔夜   ← 这是第 5 个隔夜
```

**共 5 个隔夜，不是 1 个。**

### 修正后的口径

三套收益必须分别报告：

```
口径①  收盘信号收益
        = close[T+5] / open[T+1] - 1
        含义：假设能在 T+5 收盘价卖出（现实中做不到，T+5 收盘时才知道信号）

口径②  实际成交收益
        = open[T+6] / open[T+1] - 1
        含义：T+5 收盘出信号，T+6 开盘卖（真实可执行）

口径③  隔夜损耗
        = 口径② - 口径①
        = open[T+6] / close[T+5] - 1
        含义：第 5 个隔夜跳空的贡献
```

**三个数都要报。如果口径③系统性为负，说明"持有到第 5 天才卖"这个决策本身有成本。**
