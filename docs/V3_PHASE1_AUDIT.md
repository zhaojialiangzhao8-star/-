## 一、当前系统架构评估

### 技术栈实况

```
后端   FastAPI + Polars + Parquet + SQLite     132 文件 / 9,918 行
前端   React 18 + Vite + Tailwind + lightweight-charts   18 文件 / 4,363 行
脚本   38 个（采集 / 回测 / 诊断 / 报告）
打包   PyInstaller onedir → 251 MB 单 exe
```

### 模块划分

| 模块 | 文件 | 行数 | 职责 |
|---|---|---|---|
| `app/backtest/` | 8 | 888 | 撮合、组合、风控、指标 |
| `app/infrastructure/` | 15 | 1,373 | 数据源（东财/腾讯/新浪/通达信）、存储、实时 |
| `app/modules/` | 15 | 1,473 | 选股批处理、板块、个股档案、AI、任务队列 |
| `app/strategies/` | 74 | 3,334 | 策略插件 + 共享算子库 |
| `app/mcp/` | 2 | 492 | MCP 工具暴露 |
| 顶层 `api.py` | 1 | 670 | 主 API |

### 架构优点

1. **数据代际机制**（`GenerationStore`）：原子切换、fail-closed、不返回空数据掩盖问题 —— 这个设计是对的，V3 应该沿用
2. **策略插件契约清晰**：一个 `.py` + `META` + `filter_frame()`，加载失败不拖垮全局
3. **派生列集中生成**（`indicators.py`）：策略不自己算均线，避免口径分裂
4. **回测撮合已经处理了 A 股特有约束**：涨停不买、一字板不成交、T+1、100 股整数倍、真实费用

### 架构缺点

1. **`api.py` 670 行单文件**，V2 新增的 router 都靠手工 `include_router`，再加 8 个页面会失控
2. **没有服务层**：API 直接操作 Parquet，没有 `Research → Signal → Portfolio` 的分层
3. **没有实验管理**：所有回测都靠脚本临时跑，结果散落在 markdown 里，无法追溯"这个数字是哪次跑的"
4. **没有因子层**：`indicators.py` 81 行只算了 12 个技术派生列

## 三、现有回测引擎的不足

### 已经做得好的

```python
# broker.py 的核心判据
if high_lim > 0 and bar.open >= high_lim - 1e-6:
    return False, RejectReason.LIMIT_UP        # 开盘涨停 → 买不进
if bar.is_one_word and bar.open <= low_lim + 1e-6:
    return False, RejectReason.LIMIT_DOWN      # 一字跌停 → 卖不出
```

这个判据比市面上大部分开源回测框架严格。

### 六个硬伤

**1. 只支持日线，无法做 30 分钟**

```python
# engine.py 的主循环
for d in trading_days:
    self._open_auction(d, day_bars)    # 开盘撮合
    self._intraday_exits(d, day_bars)  # 盘中止损（用 high/low 判断）
```

`_intraday_exits` 只能知道"今天最高价有没有碰到止损"，**不知道什么时候碰的**。改成 30 分钟可以解决，但数据没有。

**2. 盘中止损假设过于乐观**

```python
# 只要 low <= 止损价，就认为止损成交
if bar.low <= stop_price:
    self._do_sell(order, bar, d, stop_price, "stop")
```

实际跳空低开时，`low` 可能远低于 `stop_price`，成交价是 `open` 而不是 `stop_price`。**这个引擎按 `stop_price` 成交，等于假设永远没有跳空滑点。**

**3. 没有信号量控制**

回测把策略吐出的**全部信号**都丢给撮合器，被拒的靠 `max_positions` 兜底。实测：

```
三不高（已停用）  被拒 1,321,072 次
因子合成（已停用）被拒   112,830 次
均值回归（仍在用）被拒    77,775 次
```

**被拒 100 万次意味着"从 100 万个信号里随机抽 1,857 个"**，这个数字没有统计意义。正确做法是每天只取 score 前 N 个。

**4. 没有 Walk-Forward / 样本外机制**

现在只有"整段跑一次"。V3 要求的滚动验证、参数敏感性、成本压力测试，全部要新写。

**5. 没有组合层**

一次只能跑一个策略。V3 要求"多策略共享资金池、计算相关性、控制行业集中度"—— 需要新的 portfolio 层。

**6. 指标缺三项**

```
缺 盈利因子（profit factor）  ← V3 门槛要求 ≥1.2
缺 换手率
缺 成本占比
```

`payoff`（盈亏比）有，但 `profit_factor = 总盈利 / 总亏损` 没有独立计算。

### 四个质量问题（按严重程度）

**问题 1：历史长度严重不足（最严重）**

```
每只 K 线数：最少 194   中位 565   最多 1,325
起始日早于 2021-06 的标的：      12 只
起始日晚于 2022-01 的标的：  4,772 只（99.7%）
少于 1000 只的交易日：         770 个 / 1,335（58%）
```

**中位数只有 565 根 = 2.3 年**。所谓"5 年回测"实际有效区间只有 **2024 年以后**。

原因是腾讯 `hfq` 接口单次给的历史长度不一致，之前换成腾讯源时没有补齐。

**这直接否定了现有所有回测结论的有效性** —— 所有策略都只在 2 年数据上测过。

**问题 2：今天（11-12）的数据复权基准错了**

```
复权跳变 2,516 行，其中 2,485 只集中在 2026-11-12

万科A  11-11: 1206.66  →  11-12: 368.24（-69.5%）
       真实价 3.14，倍数从 377 变成 117
```

盘中采集导致当天数据用了不同复权基准。**已在 `indicators.py` 加了熔断（|chg|>21% 剔除），但还没重新发布代际。**

**问题 3：没有任何基本面数据**

V3 的六大引擎里，**"多因子选股"有一半因子做不了**：

```
动量因子   ✅ 可算（5/10/20/60日收益）
价值因子   ✗ PE/PB/PS/股息率/自由现金流 全无
质量因子   ✗ ROE/ROA/毛利率/净利率/经营现金流/负债率 全无
成长因子   ✗ 营收增长/净利增长/扣非增长 全无
交易行为   ⚠️ 部分（换手率是代理值，量比/振幅可算，资金流向无）
风险因子   ✅ 可算（波动率/回撤/下行波动/流动性）
```

**六个大类里，三个完全做不了。**

**问题 4：没有行业分类历史**

行业中性化需要"某只股票在某个日期属于哪个行业"。现在只有同花顺当前快照，**没有历史归属**，也无法回测"行业轮动"。

## 五、已有策略的有效性问题

### 完整审计结果（63 组回测，`reports/strategy_audit.md`）

**持有 5 天排名**：

```
#   策略                     收益      夏普   胜率   被拒订单
1   因子合成 IC6            +93.0%   0.72   44.7%  112,830   ← 已停用
2   缩量连涨创新高           +74.0%   0.62   41.5%    1,461
3   RSI超卖回升             +55.8%   0.57   46.6%   82,633   ← 数字不可信
4   InStock·低回撤增长       +47.6%   0.47   41.6%    6,812
5   援军战法                +12.0%   0.22   45.5%  152,145   ← 已停用
6   布林收口突破             +9.9%   0.20   41.9%   54,418   ← 数字不可信
7   InStock·高而窄旗形        +8.4%   0.19   38.1%    1,729
8   均值回归超跌              +4.6%   0.14   45.4%    7,775
────────────────────────────────────────────────────────
9-21  全部负收益
```

### 三个核心结论

**1. 表面上 8 个正收益，但只有 3 个数字可信**

被拒订单超过 5 万次的策略，回测结果等于随机抽样：

```
可信：  缩量连涨创新高（1,461 次被拒）、低回撤增长（6,812）、高窄旗形（1,729）
不可信：RSI超卖（82,633）、布林收口（54,418）、均值回归（7,775）
```

**2. 持有期极度不稳定**

```
                     5天      10天      20天
InStock·低回撤增长    +47.6%   +48.2%   +25.3%   ← 唯一三期都正
缩量连涨创新高        +74.0%    +0.2%   +27.3%   ← 10天归零
因子合成             +93.0%   +23.3%   -25.1%   ← 20天转亏
布林收口突破          +9.9%   -22.8%   -56.9%   ← 完全不可靠
```

**只有 `InStock·低回撤增长` 通过持有期稳定性检验。**

**3. 打板三件套在账户模型里必亏**

```
打板 1进2   -83.9%
打板 2进3   -71.9%
打板 3进4   -48.0%
```

原因前面查过：打板的利润全在次日高开，而账户模型正好买在高开之后。

### 根本原因

**所有 16 个策略都是技术指标衍生品，没有任何一个基于统计验证的因子。**

这正好是 V3 要解决的问题。

## 八、可能影响现有系统的风险

### 风险 1：数据重采会推翻现有回测结论

从 2 年数据换成 5 年，**现在所有策略排名都会变**。之前"缩量连涨创新高 +74%"的数字大概率会掉。

**对策**：V3 的所有策略必须在新数据上重测，旧数字作废。这一点要提前接受。

### 风险 2：基本面数据接口可能被限流

东财 `datacenter` 的财务接口现在能用，但批量拉 4,786 只 × 5 年 × 12 个指标，请求量很大。

**对策**：
- 按季度拉，不是按天
- 加 3-5 秒间隔 + 失败重试
- 拉一次全量存 Parquet，后续增量更新

### 风险 3：内存

现在 4,786 只 × 2 年 = 270 万行，exe 峰值 1.5-2 GB。扩到 5 年 = 600 万行，**预计 3-4 GB**。16 GB 机器能跑但紧张。

**对策**：
- `Bar` 已经是 `slots=True`（120 字节/行）
- 因子计算分批落盘，不一次全读进内存
- 回测用 `scan()` + 切片，不 `collect()` 全表

### 风险 4：因子无效

**这是最该预期到的结果。**

学术研究里，A 股能被验证有效的公开因子大概只有 5-8 个（规模、价值、动量、反转、波动率、换手、盈利质量）。V3 列的 31 个因子里，**大概率有一半 IC 接近 0**。

**对策**：
- 因子评估器第一版就要能输出"这个因子无效"的结论
- 不达标的因子直接标灰，不硬凑进模型
